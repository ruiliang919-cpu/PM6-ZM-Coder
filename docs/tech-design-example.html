1 背景与需求
业务背景
地铁直流照明系统需实时监控 60+ 台机柜
核心痛点
当前轮询效率低，100ms 一轮只能覆盖 20 台
目标
支持 60 台并发通信，延迟 < 500ms
优先级
P0 高优

功能需求

  • 支持 Modbus TCP 协议与机柜主控板通信（功能码 01/03/05/06）
  • 实时读取机柜状态：母线电压、电流、温度、绝缘阻值
  • 远程控制：照明开关、调光亮度、运行模式切换
  • 异常告警：过压、过流、绝缘故障、通信超时
  • 通信协议可配置，支持后续扩展 MQTT 通道

3 接口设计（API）

设备状态查询

方法路径说明
GET /zm/device/{deviceId}/status 查询单台机柜实时状态（电压/电流/温度/绝缘阻值）
GET /zm/device/list 查询所有机柜列表及在线状态
GET /zm/lighting/status 查询各区域照明状态（开关/亮度）

控制指令下发

方法路径说明
POST /zm/control/switch 照明开关控制 {"deviceId":1,"zoneId":0,"action":"on"}
POST /zm/control/dimmer 调光控制 {"deviceId":1,"zoneId":0,"brightness":80}
POST /zm/control/mode 运行模式切换 {"deviceId":1,"mode":"auto"}
POST /zm/scene/apply/{sceneId} 一键应用场景（批量控制多台设备）

告警与历史

方法路径说明
GET /zm/alarm/list 当前告警列表（分页、按设备/类型筛选）
GET /zm/history/event 历史告警事件查询
GET /zm/power/statistics 电量统计数据（日/周/月维度）

@Scheduled(fixedRate = 3000) // 每3秒轮询 public void pollDeviceStatus() { // 1. 从连接池获取 Modbus TCP 连接 ModbusConnection conn = pool.getConnection(deviceIp, port); // 2. 发送功能码 03（读保持寄存器） int[] registers = conn.readHoldingRegisters(slaveId, startAddr, count); // 3. 解析寄存器值 → 电压/电流/温度 DeviceStatus status = ProtocolParser.parse(registers); // 4. 更新 Redis 缓存 + 判断是否触发告警 redisTemplate.opsForHash().put("device:" + deviceId, status.toMap()); alarmService.checkThreshold(deviceId, status); // 5. 异步写入 MySQL（批量合并，减少IO） asyncBatchWriter.add(status); }
6 技术选型
组件选型备选方案选型理由
Modbus 通信jlibmodbusmodbus4j, jamod社区活跃、支持 TCP/RTU、连接池成熟
MQTT 客户端Eclipse Pahohivemq-clientEclipse 官方、Spring 集成好、项目已有依赖
连接池自研 + HikariCP 模式Commons Pool 2Modbus TCP 长连接特性，需自定义心跳检测
异步写入Disruptor 环形队列BlockingQueue高吞吐、低延迟、GC 友好
缓存Redis + Caffeine纯 Redis本地缓存减少网络开销，Redis 做持久化
7 风险与应对
风险影响概率应对措施
Modbus TCP 连接断开 高 中 连接池自动重连 + 指数退避 + 告警通知
设备响应超时（>2s） 中 高 指令队列超时剔除 + 设备标记离线 + 3次重试
并发控制指令冲突 中 低 设备级分布式锁（Redisson）+ 指令排队
寄存器地址变更（固件升级） 中 低 寄存器地址配置化（数据库存储），支持热更新
8 排期
第 1 周
Modbus TCP 连接池 + 协议编解码（功能码 01/03/05/06）
第 2 周

第 3 周

第 4 周
异常处理完善 + 性能压测（60台并发）+ 文档
