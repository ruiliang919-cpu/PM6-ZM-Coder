### 1.1 Modbus TCP 通讯层核心缺陷修复

**涉及文件:**
- `server/ruoyi-zm/src/main/java/com/ruoyi/zm/config/ModbusTCPManager.java` — Modbus TCP 连接池管理器

**修复前问题:**
- 竞态条件：原有代码使用 get + put 分离操作访问 ConcurrentHashMap，多线程下存在时间窗口竞态
- 连接泄漏：连接创建失败或验证失败时未及时释放已创建的资源
- 异常处理混乱：多处异常处理分散，日志记录不统一

**具体修改内容:**
- 使用 `ConcurrentHashMap.compute()` 原子操作替换原有的 get + put 模式
- 在 `createNewMaster()` 中增强异常处理，初始化失败即刻返回 null
- 新增 `destroyConnection()` 方法仅销毁连接不操作 Map（供 compute 内部使用）
- 新增 `safeDestroy()` 方法销毁连接并从 Map 移除（供外部使用）
- 使用 RedisTemplate SCAN 替代 KEYS 命令清除断线设备缓存

**修复效果:**
- 消除竞态条件，确保连接池原子一致性
- 连接泄漏风险降低，资源释放更可靠
- Redis 大 KEY 场景下不再阻塞主线程

## 二、发现的问题

### 严重问题（MUST FIX）— 共 3 个

#### 2.1 ConcurrentHashMap.compute() 内部违规调用 remove

- **文件：** `server/ruoyi-zm/src/main/java/com/ruoyi/zm/config/ModbusTCPManager.java`
- **问题描述：** `getSlave()` 使用 `masterPool.compute(slaveId, ...)` 实现原子操作，但 lambda 内调用的 `safeDestroy()` 在 finally 中执行 `masterPool.remove(slaveId)`，违反 JDK 规范（compute 映射函数执行期间不允许修改同一 Map），可能导致 `IllegalStateException` 或未定义行为。
- **影响：** 高并发场景下可能抛异常或死锁，导致设备通讯中断。
- **修复方案：** 新增 `destroyConnection()` 方法仅销毁连接不操作 Map，供 compute 内部使用；保留 `safeDestroy()` 供 compute 外部使用。
- **修复状态：** 已修复

#### 2.2 归档任务时间戳单位不匹配（毫秒 vs 秒）

- **文件：** `server/ruoyi-zm/src/main/java/com/ruoyi/zm/service/impl/PowerDataArchiveTask.java`
- **问题描述：** 数据库 `dev_base_power.timestamp` 存储秒级时间戳（如 1749008368），但代码使用 `System.currentTimeMillis()` 计算毫秒级阈值（约 1.7e12）。所有秒级时间戳均小于毫秒级阈值，条件恒为真。
- **影响：** 首次执行定时任务将删除全表所有数据，造成不可逆数据丢失。
- **修复方案：** 常量改为秒级 `ARCHIVE_THRESHOLD_SECONDS = 365L * 24 * 60 * 60`，阈值计算改为 `System.currentTimeMillis() / 1000 - ARCHIVE_THRESHOLD_SECONDS`。
- **修复状态：** 已修复

#### 2.3 归档 INSERT/DELETE 未绑定同批记录

- **文件：** `server/ruoyi-zm/src/main/java/com/ruoyi/zm/service/impl/PowerDataArchiveTask.java`
- **问题描述：** INSERT 和 DELETE 都使用 `WHERE timestamp < ? LIMIT ?` 但无 ORDER BY、无 ID 绑定，两条 SQL 可能操作不同记录集。
- **影响：** 可能导致部分记录未归档就被删除（数据丢失），或同一记录被多次归档（数据重复）。
- **修复方案：** 先查询待归档 ID 列表，再基于同一批 ID 执行 INSERT 和 DELETE，确保操作完全一致的记录集。
- **修复状态：** 已修复

### 警告问题（SHOULD FIX）— 共 4 个

#### 2.4 WebSocket 端点未鉴权

- **文件：** `server/ruoyi-admin/src/main/java/com/ruoyi/web/websocket/WebSocketConfig.java`
- **问题描述：** `setAllowedOriginPatterns("*")` 允许任意来源连接，且无 token 校验。前端虽在 URL 上带了 token，但后端未校验，等价于公开推送通道。
- **影响：** 任何能访问服务器的客户端可订阅设备状态和告警信息，存在信息泄露安全风险。
- **修复方案：** 新增 `WebSocketAuthInterceptor` 内部类，在握手阶段使用 Sa-Token 的 `StpUtil.getLoginIdByToken(token)` 校验，校验失败拒绝握手。
- **修复状态：** 已修复

#### 2.5 登出后 WebSocket 仍自动重连

- **文件：** `web/src/utils/websocket.js`
- **问题描述：** `disconnectWebSocket()` 调用 `ws.close()` 后，`onclose` 回调仍触发 `scheduleReconnect()`，导致登出后持续向后端发起未授权连接。
- **影响：** 登出后产生无效连接请求，增加服务器日志噪音和网络开销。
- **修复方案：** 添加 `shouldReconnect` 标志位，`disconnectWebSocket()` 中设为 false，`scheduleReconnect()` 和 `onclose` 中检查该标志。
- **修复状态：** 已修复

#### 2.6 BaseProtocolServiceImpl.queryById 永远返回 null

- **文件：** `server/ruoyi-zm/src/main/java/com/ruoyi/zm/service/impl/BaseProtocolServiceImpl.java`
- **问题描述：** 泛型基类中 `queryById(Long id)` 直接 `return null`，4 个协议 Service 继承后调用此方法均无法正确查询。
- **影响：** 按 ID 查询协议配置的 API 全部返回空。
- **修复方案：** 实现为 `return baseMapper.selectVoById(id)`，添加 null 保护。
- **修复状态：** 已修复

#### 2.7 首页功率 WebSocket 推送链路不完整

- **文件：** `server/ruoyi-admin/src/main/java/com/ruoyi/send/Update03DataService.java`
- **问题描述：** 前端已订阅 `/topic/device/power`，后端定义了 `pushPowerData()` 方法，但无调用方。前端仅靠 30s 轮询刷新。
- **影响：** WebSocket 推送功能名存实亡，首页功率图表无法实时更新。
- **修复方案：** 在 `Update03DataService.Fun0x0000()` 方法末尾（功率数据写入完成后），注入并调用 `deviceStatusPushService.pushPowerData()`。
- **修复状态：** 已修复

### 建议（CONSIDER）— 共 1 个

#### 2.8 设备离线检测 Redis TTL 与配置化 TTL 不一致

- **文件：** `server/ruoyi-admin/src/main/java/com/ruoyi/mqtt/DeviceOnlineCheckTask.java`
- **问题描述：** `ModbusTCPManager` 使用配置化的 `modbusProperties.getConnectionTtl()` 秒，但 `DeviceOnlineCheckTask` 标记离线时固定使用 `1 DAY` TTL。
- **影响：** 同一 Redis key 在不同路径下过期策略不一致，增加维护复杂度。
- **修复建议：** 统一注入 `ModbusProperties`，使用相同的 TTL 配置值。
- **修复状态：** 待修复（低优先级，不影响功能）

## 三、遗留风险

1. **WebSocket 鉴权依赖 URL 明文 token** — 虽已添加服务端校验，但 token 通过 URL 参数传递在日志中可能泄露，后续可考虑改为通过 STOMP CONNECT 帧 header 传递。
2. **功率推送频率** — 当前在每次 Modbus 03 功能码数据更新时都会推送，如果设备数量大且更新频繁，WebSocket 推送量可能较高，后续可考虑节流。
3. **数据库索引变更** — 添加索引的 ALTER TABLE 语句在大表上执行可能锁表，生产环境应在维护窗口操作。
4. **Redis TTL 不一致** — 如建议 2.8 所述，暂不影响功能但增加理解成本。
