📋 1. 项目概述

PM6-ZM 是一套面向直流照明场景的 集中监控管理系统，用于对配电柜/电源柜、照明回路、传感器、场景策略等进行统一监控与远程控制。

🏭 应用场景

隧道、地铁、管廊、工厂等需要直流照明集中管控的工业场景

📡 通信协议

同时支持 MQTT (1883)、Modbus TCP (1503/1504)、HTTP REST (8081) 三种协议

🖥️ 多端支持

Web 管理后台 + Electron 桌面客户端，支持 Windows 部署

📊 实时监控

WebSocket 实时推送设备状态，ECharts 可视化数据看板

💡 5. 核心业务分析

5.1 业务域划分

系统围绕 "设备 → 回路 → 分区 → 场景" 四级层次构建照明管控能力：

场景 (Scene) ← 最高层：一键切换整体照明方案 │ ├── 分区 (District) ← 中间层：按物理区域分组控制 │ │ │ ├── 回路 (Loop/Branch) ← 执行层：单条照明线路开关/调光 │ │ │ └── 传感器 (Sensor) ← 感知层：红外/照度传感自动触发 │ └── 机柜 (Device/Cabinet) ← 底层：配电柜/电源柜硬件实体

5.2 核心业务功能矩阵

🖥️ 设备管理

机柜注册、上下线检测、运行状态监控（母线电压/电流/温度/绝缘阻值）、设备参数远程读写

💡 照明控制

单回路开关、分组控制、调光控制、一键全亮/全灭、AC/DC 切换

📍 分区管理

物理区域划分、分区亮度设置、分区开关状态、分区与回路绑定

🎬 场景管理

场景创建/编辑、场景切换、场景时控、场景与分区关联

⏱️ 定时控制

时控策略配置、普通时控/场景时控、AC 定时控制、周期性任务调度

📊 能耗统计

电表数据采集（瞬时/日/周/月/季/年）、功率计算、能耗分析报表

⚠️ 告警管理

故障记录（ACDC/DCDC/母线/回路）、漏电检测、告警列表与历史查询

📡 传感器

红外传感器组配置、照度传感器组配置、传感器联动策略

📡 7. 通信协议层

系统支持三种并行通信方式，分别服务于不同的设备接入场景：

7.1 MQTT 协议 (端口 1883)

  • Broker：EMQX，通过 Spring Integration MQTT 集成
  • 消息入口：MqttMessageHandler — 使用 @ServiceActivator(inputChannel = "mqttInputChannel") 接收
  • 消息发布：MqttPublisher — 发布遥调/遥控指令
  • 心跳检测：DeviceOnlineCheckTask — 定时检查设备在线状态
  • 协议解析：mqtt03/addr03/ 目录下按寄存器地址分发处理器（工厂模式）
  • 心跳数据：Heart VO — 设备周期上报的状态包
MQTT 消息按 Topic 分层路由：设备类型/设备ID/功能码，由 MqttMessageHandler 解析 Topic 后分发到对应的处理链。

7.2 Modbus TCP (端口 1503/1504)

  • 从站模式：Slave 类 — 启动 Modbus TCP Slave (端口 1504)，供 BAS 等第三方系统读取数据
  • 主站模式：ModbusTCPManager — 主动连接设备 Modbus 端口 (1503)，下发读写指令
  • 功能码支持：
    • FC01/03 — 读线圈/读寄存器 (遥测)
    • FC05 — 写单线圈 (遥控，开关控制)
    • FC06 — 写单寄存器 (遥调，参数设置)
  • 指令队列：DevInstruct → WriteBusinessService → Modbus 写入 → DevWriteInstruct (结果记录)

7.3 HTTP REST (端口 8081)

  • 前端 Vue 应用通过 HTTP API 与后端交互
  • 遵循 RESTful 风格，统一响应格式 R<T>
  • Sa-Token + JWT 认证，RBAC 权限控制

7.4 WebSocket

  • DeviceStatusPushService — 设备状态变更时实时推送到前端
  • 前端通过 WebSocket 接收设备在线/离线、告警等实时事件

⚡ 8. 缓存架构

系统采用 Redis + Caffeine 二级缓存 架构，针对高频读取的设备状态数据做了深度优化：

8.1 缓存类清单

缓存类缓存对象用途
DeviceCache / DeviceCachePlus设备基础信息设备列表快速查询
DeviceProcessorCache设备处理器协议处理链缓存
LightingCache照明状态回路开关/亮度状态
GroupCache分组信息回路分组数据
SceneCache / SceneControlCache场景数据场景配置与控制
AcDcCache / AcSwitchCacheAC/DC 状态交直流切换状态

LeakageCache漏电数据漏电检测值

OtherSwitchCache其他开关非照明开关状态
LoopByGroupCache / ZoneUtilCache回路/分区分区回路映射

8.2 缓存 Key 设计

Key 和 Keys 类统一管理 Redis Key 前缀，避免 Key 冲突。典型 Key 模式：

zm:device:{deviceId}          // 设备状态
zm:lighting:{deviceId}        // 照明状态
zm:group:{deviceId}           // 分组数据
zm:scene:{deviceId}           // 场景数据
zm:update:{deviceId}:*        // 更新标记
zm:instruct:{slaveId}:*       // 指令队列
⚠️ 缓存数据通过 MQTT 心跳和 Modbus 轮询实时更新，ModuleGuard 负责缓存一致性守护。

📐 13. 架构评价与建议

13.1 架构优势

✅ 成熟框架

基于 RuoYi-Vue-Plus v4.8.0，开箱即用的 RBAC 权限、日志、代码生成等基础能力

✅ 多协议支持

MQTT + Modbus TCP + HTTP REST 三协议并行，灵活对接各类设备与第三方系统

✅ 高性能缓存

Redis + Caffeine 二级缓存，20+ 精细化缓存类覆盖所有高频读取场景

✅ 实时推送

WebSocket 设备状态实时推送，用户无需轮询即可获取最新状态

13.2 改进建议

类别现状建议
前端框架 Vue 2.6 已进入维护模式 中期规划迁移至 Vue 3 + Composition API，Element Plus
模块职责 ruoyi-zm 模块承载了通信、缓存、业务全部逻辑 可拆分为 ruoyi-zm-device (设备)、ruoyi-zm-protocol (协议)、ruoyi-zm-control (控制)
单元测试 测试覆盖较少 补充 Service 层单元测试，特别是协议解析与缓存逻辑
可观测性 已有 Spring Boot Admin 可接入 Prometheus + Grafana 做更细粒度的指标监控
文档 docs/ 目录已有协议文档 补充 API 接口文档 (可利用 SpringDoc 自动生成)、部署运维手册
