前端文件结构

核心目录说明
核心结论：前端文件夹虽多，你只需要关注两个目录：api/（接口定义）和 views/（页面代码）。其他都是框架文件，基本不用动。
📁 src/ 根目录
src/ ├── main.js ← 程序入口，不用动 ├── App.vue ← 根组件，不用动 ├── permission.js ← 权限控制，不用动 ├── settings.js ← 配置项，不用动 ├── router/ ← 路由配置 ├── store/ ← 全局状态 ├── utils/ ← 工具函数 ├── components/ ← 公共组件 ├── layout/ ← 页面布局 ├── plugins/ ← 插件 ├── mixins/ ← 混入 ├── directive/ ← 指令 ├── assets/ ← 图片/样式 ├── api/ ← ⭐ 接口定义 └── views/ ← ⭐ 页面代码
📁 views/zm/ 业务页面
views/ ├── index.vue ← 首页（图表） ├── login.vue ← 登录页 └── zm/ ← 业务页面 ├── baseRegion/ ← 区域管理 ├── baseDistrict/ ← 分区管理 ├── baseScene/ ← 场景管理 ├── baseDevice/ ← 机柜配置 ├── baseControl/ ← 照明控制 ├── baseStatus/ ← 照明状态 ├── baseInstructs/ ← 指令管理 ├── alarm/ ← 告警列表 ├── history/ ← 历史记录 └── device/ ← 机柜详情 ├── dev/ ← 机柜信息 ├── dev-control/ ← 机柜控制 ├── record/ ← 机柜记录 └── setting/ ← 机柜设置
📁 api/zm/ 接口定义文件
api/zm/ ├── baseRegion.js ← listBaseRegion, addBaseRegion, updateBaseRegion, delBaseRegion ├── baseDistrict.js ← listBaseDistrict, addBaseDistrict, updateBaseDistrict, delBaseDistrict ├── baseScene.js ← listBaseScene, getBaseScene, addBaseScene, updateBaseScene, delBaseScene ├── baseDevice.js ← listBaseDevice, getBaseDevice, baseDeviceInit ├── baseControl.js ← zoneControlList, updateSimpleControl ├── baseStatus.js ← lightList ├── alarm.js ← getFaultSeven, getNews ├── history.js ← getRecordSeven, getFaultAll, exportRecord ├── device/info.js ← acList, dccList, busInfo ├── device/control.js ← updateSimpleControl, loopControlSwitch ├── device/record.js ← getRecordOne, getFaultSeven ├── device/setting.js ← getStatus, setStatus └── ...
一个页面 = 两个文件：
views/zm/baseScene/index.vue → 页面长什么样（表格、按钮、弹窗）
api/zm/baseScene.js → 调用哪些接口（list、add、edit、delete）

组件关系：页面 vs 子组件

核心概念：一个页面（index.vue）可以包含多个子组件（components/xxx/index.vue）。子组件不是独立页面，而是页面里的一块区域。
📐 页面与组件的关系
一个页面 (index.vue) │ ├── 子组件A (components/A/index.vue) ← 页面里的一块区域 │ └── 子子组件 (components/A/table.vue) ← 区域里的小块 │ ├── 子组件B (components/B/index.vue) ← 页面里的另一块区域 │ └── 子组件C (components/C/index.vue) ← 页面里的又一块区域 举例：机柜信息页面 ┌────────────────────────────────────────────┐ │ ┌──────────────┐ ┌──────────────┐ │ │ │ JiaoLiuHuiLu │ │ ZhiLiuHuiLu │ │ ← Tab "回路信息" 里的两个子组件 │ │ 交流回路表格 │ │ 直流回路表格 │ │ │ └──────────────┘ └──────────────┘ │ └────────────────────────────────────────────┘

device/dev/ ├── index.vue ← 主页面（Tab 容器） └── components/ ├── JiaoLiuHuiLu/ ← 交流回路（Tab 0） │ └── index.vue ├── ZhiLiuHuiLu/ ← 直流回路（Tab 0） │ └── index.vue ├── MuXian/ ← 母线信息（Tab 1） │ └── index.vue ├── DC/ ← 直流模块（Tab 1） │ └── index.vue ├── JueYuan/ ← 绝缘信息（Tab 2） │ └── index.vue ├── JiaoLiuXinXi/ ← 交流信息（Tab 3） │ ├── index.vue │ ├── table_left.vue ← 左侧表格子组件 │ └── table_right.vue ← 右侧表格子组件 └── ChuanGanQiXinXi/ ← 传感器信息（Tab 4） └── index.vue

Vue 文件代码模板

每个 Vue 文件都是三部分：template（页面结构）+ script（页面逻辑）+ style（页面样式）
📄 Vue 文件基本结构
<!-- template：页面长什么样 --> <template> <div> <!-- HTML 标签、Element UI 组件 --> </div> </template> <!-- script：页面怎么运作 --> <script> import xxx from './components/xxx' // 导入子组件 export default { components: { xxx }, // 注册子组件 data() { // 页面数据 return { list: [], total: 0 } }, created() { // 页面加载时执行 this.getList() }, methods: { // 页面方法 getList() { /* 调接口获取数据 */ }, handleAdd() { /* 点新增按钮 */ }, handleDelete() { /* 点删除按钮 */ } } } </script> <!-- style：页面样式 --> <style scoped lang="scss"> /* CSS 样式，scoped 表示只作用于当前组件 */ </style>
📄 按钮与 API 的三种关系
❌ 按钮不调 API（纯前端操作）
handleAdd() { this.reset() // 清空表单 this.open = true // 打开弹窗 this.title = "添加场景" }

点击后只是弹出对话框，没有发网络请求。
常见：新增（弹窗）、取消（关弹窗）、重置表单。

✅ 按钮调 1 个 API
handleExport() { this.download( 'zm/baseScene/export', { ...this.queryParams } ) }

只调 1 个接口。
常见：导出、搜索、页面加载。

✅✅ 按钮调多个 API（最常见）
submitForm() { if (this.form.id != null) { updateBaseScene(this.form).then(() => { // API 1: 修改 this.open = false this.getList() // API 2: 刷新列表 }) } else { addBaseScene(this.form).then(() => { // API 1: 新增 this.open = false this.getList() // API 2: 刷新列表 }) } }

点一次"确定"发 2 个请求：先提交数据，再刷新列表。
常见：确定提交、删除（删完再刷新）。

数据流转：从点击到显示

🔄 CRUD 页面数据流转（以场景管理为例）
页面加载时： created() → this.getList() ↓ listBaseScene(queryParams) ← api/zm/baseScene.js ↓ request({ url: '/zm/baseScene/list', method: 'post' }) ← Axios 发 HTTP 请求 ↓ POST /zm/baseScene/list → DevBaseSceneController → Service → MySQL ↓ 返回 { rows: [...], total: 100 } ↓ this.baseSceneList = response.rows ← 赋值给 data ↓ <el-table :data="baseSceneList"> ← 自动渲染表格 用户点击"确定"时： submitForm() → this.$refs.form.validate() ↓ 验证通过 → addBaseScene(this.form) ← 调新增接口 ↓ POST /zm/baseScene/add → Controller → Service → MySQL INSERT ↓ 返回 { code: 200 } ↓ this.$modal.msgSuccess("新增成功") ← 弹成功提示 ↓ this.getList() ← 再调一次 list 刷新表格
🔄 Tab 页面数据流转（以机柜信息为例）
页面加载时： created() → currentIndex = 0（默认显示第一个 Tab） ↓ v-if="currentIndex === 0" 成立 ↓ 加载 <JiaoLiuHuiLu/> 和 <ZhiLiuHuiLu/> 组件 ↓ 每个子组件自己的 created() 里调各自的接口获取数据 用户点击 Tab 时： 用户点击 "直流信息" Tab ↓ currentIndex 变成 1 ↓ v-if="currentIndex === 1" 成立 ↓ 加载 <MuXian/> 和 <DC/> 组件 ↓ 这两个子组件各自的 created() 里调各自的接口

总结

📌 核心结论
问题答案
前端文件夹那么多，我怎么知道哪个是哪个？只关注 api/ 和 views/，其他都是框架文件不用动
一个 index.vue 对应什么？一个 index.vue = 一个页面 = 浏览器里看到的一个界面
每个按钮都调 API 吗？不一定。30% 不调 API（纯前端），40% 调 1 个，30% 调多个
所有页面布局都一样吗？不一样。有 4-5 种布局，但 80% 是 CRUD 表格型 或 Tab 切换型
组件和页面什么关系？组件是页面里的一块区域，不是独立页面
Tab 是什么？页面顶部的标签栏，点哪个就显示哪个内容
📌 布局类型速查
布局类型使用数量特征适用场景
CRUD 表格型 7 个页面 搜索 + 表格 + 弹窗 + 分页 数据管理（区域、分区、场景、机柜、告警、记录）
Tab 切换型 5 个页面 Tab 标签栏 + 多个子组件 复杂页面（机柜信息/控制/设置/记录、照明控制）
卡片列表型 1 个页面 卡片网格 + 分页 状态展示（照明状态）
图表型 1 个页面 图表 + 表格 首页概览
纯表格型 1 个页面 只有表格 + 分页 只读数据展示（指令管理）
开发新页面时：
